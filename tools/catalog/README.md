# Каталог → данные игры

Цифры игры живут в документе «Пограничье: каталог локаций, юнитов и построек». Путь до Godot такой:

```
документ каталога → catalog.json → export.py → data/**/*.tres → CatalogDB в игре
```

| Файл | Что это |
| --- | --- |
| `catalog.json` | Копия таблиц каталога ячейка в ячейку, с датой выгрузки. Ничего не толкует. |
| `import_docs.py` | Собирает `catalog.json` из выгрузки вкладок документа в Markdown. |
| `cells.py` | Разбор ячеек: цена «50/0/20/0», урон «6 Б», броня «1/2», дальность «12 (мин. 4)», секунды в тики. |
| `rules.py` | Разбор колонки «Особое»: классы, бонусы «+6 к коннице», правила («таран ×2 после 4 клеток»). |
| `model.py` | Строит определения, раскрывает общие постройки по фракциям, проверяет ссылки. |
| `manual.json` | То, что каталог пишет только словами, и временные заплатки. У каждой записи указан источник. |
| `prototype.json` | Что грузит прототип. Для этих id экспортёр строже. |
| `export.py` | Пишет `data/` и `pending.txt`; с `--check` только сверяет. |
| `pending.txt` | Правила из «Особого», которые экспортёр ещё не понимает (у юнитов вне прототипа). |

## Как поменять цифру

1. Правим таблицу в документе каталога.
2. Выгружаем вкладки в Markdown (overview, gdl, crown, order, moscow, allies, magic, locations) (заголовки и таблицы; `python3 -m tools.catalog.import_docs --from-xml READ.json TAB.md` превращает ответ Claude Docs `read` в такой файл) и собираем `catalog.json`:
   `python3 -m tools.catalog.import_docs ПАПКА_С_ВКЛАДКАМИ`
3. `python3 -m tools.catalog.export` и коммитим `catalog.json` вместе с `data/`.

Руками `data/` не правим: `export.py --check` в CI найдёт расхождение.

## Единицы в .tres

- Время в тиках, 20 тиков в секунду: перезарядка 2,0 с → `reload_ticks = 40`.
- Скорость в тысячных клетки в секунду: 1,35 → `speed_milli = 1350`. Так ни одно число не теряет точности; перевод в фиксированную точку делает симуляция (M2).
- Множители в промилле: таран ×2,5 → `charge_permille = 2500`.
- Дух «—» → `never_flees = true`.
- Правила боя (`data/rules/combat.tres`, блок `combat_rules` в `manual.json`): целые в тех же единицах (промилле, тики, клетки, тысячные клетки `_milli`). Ключи из `_temporary` взяты временно, в каталоге их нет.
- Экономика (`data/rules/economy.tres`, блок `economy_rules` в `manual.json`, M5): скорости сбора в тысячных единицы в секунду (`gather_wood_milli = 390` — 0,39 дерева/с), запасы, лимит населения, скидки в промилле. `_temporary` — числа, которых нет в каталоге.
- Размеры и метки построек (блок `building_layout`): `sizes` по id постройки или общей постройки → `params.size_w`, `params.size_h`; `tags` (`walkable`, `in_forest`, `no_age_count`, `brick_discount`, `brickworks`, `gate`, `power_place_only`) → `tags`. Постройка без размера — ошибка экспорта. «Конница −N% цены» из «Эффекта» → `params.cavalry_discount_permille`.
- Эффекты технологий (блок `tech_effects`, → `TechDef.effects`): `gather_farm`, `gather_wood` и т. п., `farm_food`, `zaseka_speed`, `zaseka_hp` в промилле; `<класс или id юнита>.<damage_melee|damage_pierce|armor_melee|armor_pierce|range|hp_permille>` прибавками. Технологии, эффект которых ещё не сделан, лежат в `_deferred` с причиной; у технологии прототипа должно быть одно из двух.
- Рельеф (`data/terrain/`, из таблицы «Тайлы и рельеф» вкладки «Локации»): `infantry_permille`, `cavalry_permille`, `uphill_permille` (×0,9 «вверх» у холма, у остальных 1000), `passable`, `boats_only`, `siege_blocked` («Осадное не проходит»). Остальное «Особое» тайлов (дерево, руда, огонь, дальность) пока не разбирается: это следующие этапы.

## Когда экспортёр падает

- ячейка не подходит под формат (цена, урон, броня, число);
- пустая обязательная ячейка (id, имя, эпоха, цена постройки, HP);
- ссылка на несуществующую постройку, юнита, героя или заклинателя;
- HP существа во вкладке «Магия» не совпадает с таблицей юнитов;
- у юнита из прототипа в «Особом» есть фраза, которую `rules.py` не понимает, или он из Державы.

Новую фразу в «Особом» учим в `rules.py` (таблица `RULES`) и добавляем тест в `tests/test_rules.py`.
